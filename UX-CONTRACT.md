# ChromaScript interaction contract

The unified workspace uses `projects.ts` to load all bounded `list_projects` pages. The native project picker has no fixed 50/200-project cutoff. Publish only a complete successful read, deduplicate IDs across shifted pages, and preserve prior lists, selection and drafts on errors. Library reads abort on project/page changes and refresh; failed animation discovery does not hide successfully loaded projects or WGSL works.

MotionPreview keeps a mounted preview's message channel usable after a runtime/GPU error, so pointer and keyboard seeking can recover without recompiling. Frame position changes only on a valid rendered-frame acknowledgement. A successful frame clears only that picture's runtime error; it never clears a replacement draft's compilation/startup failure. Failed or timed-out candidates remain rejected.

New animation jobs freeze destination-v1 storage: float EXR or SDR screenshot intermediates and selected video render in a task-owned staging directory on the export volume, then publish by rename. In master mode cancellation/interruption retains verified frames; resume checks frozen source/runtime/OCIO/GPU and per-frame hashes. Workspace contains job metadata/logs only. Artifact IDs use bundle-relative paths and resolve both staging and published locations from the frozen snapshot. master-archive is a virtual ZIP64 native download with no server-side ZIP or stored byte size; export_artifact exposes the same capability on CLI/MCP. ZIP downloads restart after interruption and close their generator on disconnect. Historic artifacts keep workspace defaults; no existing task files or snapshots are migrated. Result copy explains the on-demand download without changing draft, focus, preview or output precision behavior.
Product evidence: the accepted ChromaScript plan, shared Python models, and the operation registry.
Locale: zh-CN. Dates use Asia/Taipei; units and code identifiers remain explicit.

Master-first animation delivery: new blank animations use the float engine; SDR remains explicitly selectable. Final output defaults to ACEScg Float32 ZIP masters only and 2×2 spatial supersampling, with 1×1 and 4×4 alternatives; the low-resolution preview stays single-sampled. MotionWorkbench owns editable positive-integer custom dimensions/frame count and a rational numerator/denominator text field alongside rate presets. GPU, memory and codec limitations fail explicitly. Use existing Field, Button, Modal and Notice tokens; no new visual tokens. Regenerate/check tokens.css from the unchanged frontmatter.

MotionWorkbench distinguishes measured float-pipeline verification from revision-bound source-color review. An optional shared Modal records reviewer and evidence against the revision captured when opened; conflicts retain form text, and cancellation changes no review. A saved review is an explicit attestation, not automatic shader certification. Unreviewed shaders remain usable. Dirty/new revisions show unreviewed; job results show the frozen review and independent native video tag verification.

Both animation engines stage intermediate frames, bundler outputs, encoder files and final output on the selected export volume. Workspace keeps task metadata/logs; system browser temporary profiles may remain local. Missing/replaced volume fails rather than falling back locally. DeliveryDestination explains direct external-disk writing. Master-mode float recovery retains verified EXRs; video-only and SDR rerender on retry.

Mandatory exact video-tag policy supersedes the earlier MOV declaration-only workflow described in historical sections: all standard display video output must have native gamut and transfer tags matching actual pixel encoding. Default SDR is Rec.709/sRGB. Pure Gamma 2.4/2.6 and legacy AP1/ACEScct video remain visible but disabled with a reason, across all containers, CLI/MCP and legacy presets. Comments and unspecified tags cannot satisfy the requirement. EXR scene encodings and DPX numeric Gamma remain available. Missing/mismatched actual codec tags or MOV/MP4 colr prevents publication.

App and WorkspaceLibrary own the single project/work selection and five stages for every source type. MotionWorkbench is a retained renderer adapter, with MotionSpec and motion_scene/motion_revision as its source of truth. Switching between WGSL and the current animation never reloads their drafts. Shared project changes guard both adapters, including a hidden dirty draft, and clear the outgoing context immediately. Replacing an animation (including Three.js ↔ React) retains its revision-safe discard guard. CodeEditor and PreviewTimeline are shared; each preview adapter keeps its own rational clock, last good picture and source-specific precision. Export and results use common stages; no preview writes a revision or submits a job. No existing database records, revisions or artifacts are migrated. The existing SceneSpec/ACEScg contract below applies to WGSL. TypeScript code and canvas/time drafts survive navigation. Explicit saves detect revision conflicts and never replace newer edits with a late acknowledgement. Animation/project replacement guards unsaved drafts through Modal; creation selects the new animation. With a project loaded and no animation open, guidance points to the picker and template actions without adding duplicate controls. Saved animation and job lists have bounded pagination. MotionPreview debounces unsaved drafts outside IME composition and never saves/submits a job. Obsolete replies are discarded; candidates mount before replacing the last working picture. Errors retain drafts and the last picture with explicit stale/error status and a retry action. Playback begins only on Play, pauses when hidden, and supports keyboard seeking.

The visible animation editor reads the currently open animation through get_motion_scene once per second after each completed read. HTTP/MCP/CLI saves share this revision source. A changed revision replaces a clean draft's complete code/name/canvas/time specification and selected library metadata without remounting the editor or moving focus; MotionPreview independently compiles the accepted source and never starts playback or a render job. Dirty drafts retain their original expected_revision_id and all fields, with persistent external-update feedback and the existing copy/reload/discard controls. New animations never replace the current selection automatically. Reads are serial and time out after 10 seconds; explicit operations, IME composition in code or metadata, inactive views and hidden documents suspend/cancel them. Return to a visible editor triggers an immediate check. Late responses must recheck project, animation, saved revision and current draft before application. Failed reads retry after 2 and 4 seconds, then pause after the third consecutive failure; the existing connection control resumes synchronization. Sync feedback owns its errors and cannot clear explicit save/conflict feedback. Polling writes no revisions, artifacts or jobs.

The three-float-v1 engine uses only local Three.js imports in an opaque-origin allow-scripts iframe without editor tokens/same-origin access. Source returns scene/camera/update from a factory; SDR remotion-sdr-v1 compositions independently support React DOM/SVG/ThreeCanvas; historical records without an engine normalize to SDR on read, never by rewriting stored data. GPU RGBA32F render/readback is verified using negative, >1 and non-half-representable values. Numeric float source RGB follows MotionSpec.source_color_space: linear Rec.709 (legacy default), linear BT.2020 (new blank default), ACEScg/AP1 or ACES2065-1/AP0. The host configures Three before module evaluation, unassociates linear alpha and converts through pinned linear OCIO to ACEScg/AP1. Alpha never enters OCIO. Float EXR preserves original RGB without display rendering; preview uses the generated OCIO ACES 2.0 SDR sRGB shader. Float export offers EXR Half/Float with optional video, or video-only SDR H.264 / HEVC Main10 PQ/HLG / Apple ProRes 422 HQ MOV (sRGB, PQ, HLG). Float video uses one ACES output transform; PQ/HLG target 1000 nits. ProRes is opaque 10-bit 4:2:2, budgets compressed HQ macroblocks without percentage margins, and publishes with video/quicktime MIME. HDR is never shown as an ordinary in-page video; results use an sRGB thumbnail. Native fields from get_motion_delivery_options control output choices and explain missing encoders. Video requires even dimensions, EXR allows odd dimensions. Submission freezes output, source, revision, rational rate, runtime, OCIO and destination. SDR sources offer sRGB H.264 or ProRes 422 HQ with no ACES view and no float/HDR precision claim. Source-specific output discovery is stale-safe; switching source cannot submit incompatible previous options. Every EXR is read back and verified; actual video decoding verifies codec/depth/rate/color tags. No invented HDR mastering metadata. Failures retain drafts; master-mode retry reuses verified EXRs, video-only retries restart from zero. Both refuse source/runtime/OCIO drift. Publication is atomic at the frozen destination. All discovery, compilation, transient frame preview, export and original-pixel inspection are exposed through the shared HTTP/CLI/MCP registry. render_motion_frame returns native PNG content plus original ACEScg statistics without storing a job or revision.

Animation discovery loads projects, templates, capabilities and export options independently. Successful project reads remain usable when another discovery call fails. Loading and failed project reads never imply an empty workspace or invite creation of replacement projects. Missing-operation HTTP 404/405 responses explain that the local service must be restarted, with explicit reconnect/retry; mutations are not replayed. A successful discovery retry clears its own errors without discarding drafts or save/conflict feedback. An idle local service upgrade preserves all stored records and the current browser editing session.
Create keeps the new item selected. Cancel returns to the same view. Archive is reversible and the server rejects active jobs. Cancelling a job preserves cached frames; resumption is an explicit action.
No automatic recurring render jobs. Polling reads state and never submits jobs. The visible live-preview view may render transient draft images on edits and during explicitly started playback. Late project/scene/image responses must not replace a newer selection.
Loading reserves media geometry. Errors remain visible with correction/retry actions. A disconnected server preserves drafts and provides reconnect. Searches are local, clear immediately, use pagination and never submit during IME composition.
Keyboard operation uses native semantics. Dialogs trap focus natively, support Escape, and restore focus. Pixel sampling has a keyboard center-sample alternative. No drag-only functionality.
Shared Button activation focuses its trigger before running the action, including WebKit pointer activation, so native dialogs and expanded viewers can restore the actual opener consistently.
MCP tools and CLI share identical operations. Every product capability has an operation entry and generated schema. There is no permanent-delete UI or external publication in v1.

Scene color selection uses display-referred OKLCH (D65) for the sRGB SDR preview. It is a perceptual selection space, not an HDR appearance simulation. `resolve_color` inspects RGB without changing it, or reduces requested chroma at fixed lightness/hue to fit sRGB, inverts the exact ACES preview view, and returns RGB in the parameter's declared space. The selected color is forward-rendered for verification; sRGB-declared parameters use the inverse utility input encoding. Alpha is outside this RGB-only operation. Negative and >1 original values are never clamped in storage. Errors retain advanced RGB access and offer retry; viewing limits and gamut adjustments are shown in text.

Scene-linear and scene-log ACES outputs are EXR workflows; ACEScct uses AP1 log and preserves unbounded float values. Native video tags cannot describe AP1/ACEScct exactly, so new log video is unavailable. Scene encodings have no target display peak luminance.

Code generation and internal processing are fixed float32 linear ACEScg (AP1). SceneSpec.code always returns straight-alpha ACEScg; literal RGB follows the same contract. Display delivery applies one ACES output transform, while ACES scene encodings bypass display rendering. Alpha bypasses color processing and original extended RGB is preserved. Existing shared discovery and documentation operations expose this contract equally to HTTP, MCP and CLI.
