Locale: zh-CN. Dates use Asia/Taipei; units and code identifiers remain explicit.

Mutations are pessimistic; keep values until confirmed and disable duplicate submits. Saving code sends expected_revision_id. Conflicts preserve the local draft and offer reload/copy. Scene/project changes guard unsaved drafts; browser beforeunload is used only when dirty.

MotionWorkbench and CodeEditor own the independent “动画代码” session, with MotionSpec and motion_scene/motion_revision as its source of truth. The existing SceneSpec/ACEScg contract below applies to WGSL. TSX code and canvas/time drafts survive navigation. Explicit saves detect revision conflicts and never replace newer edits with a late acknowledgement. Animation/project replacement guards unsaved drafts through Modal; creation selects the new animation. Saved animation and job lists have bounded pagination. MotionPreview debounces unsaved drafts outside IME composition and never saves/submits a job. Obsolete replies are discarded; candidates mount before replacing the last working picture. Errors retain drafts and the last picture with explicit stale/error status and a retry action. Playback begins only on Play, pauses when hidden, and supports keyboard seeking.

The browser engine uses local allowlisted packages and an opaque-origin allow-scripts iframe without editor tokens or same-origin access. Offline export compiles browser code without evaluating it in Node and disables network assets through document policy. Browser screenshots are 8-bit sRGB, not float/scene-linear masters; no ACES view is applied. MP4 composites transparency on black in linear sRGB and uses the shared FFmpeg encoder with exact rational fps. Reports verify actual decoded properties and distinguish source precision from encoder-pipe precision. Export freezes saved source/revision/runtime/destination with an idempotency key. Shared queue operations provide inspection, cancellation and explicit retry; retry rerenders browser frames and refuses changed dependencies. Export failures preserve verified files, and atomic bundle publication checks the frozen selected destination. DeliveryDestination's animation variant shares the canonical controls. Every animation operation is exposed identically to HTTP, CLI and MCP. Browser, conflict, error recovery, real 2D/3D exports and transport/schema tests provide verification.

Animation discovery loads projects, templates, capabilities and export options independently. Successful project reads remain usable when another discovery call fails. Loading and failed project reads never imply an empty workspace or invite creation of replacement projects. Missing-operation HTTP 404/405 responses explain that the local service must be restarted, with explicit reconnect/retry; mutations are not replayed. A successful discovery retry clears its own errors without discarding drafts or save/conflict feedback. An idle local service upgrade preserves all stored records and the current browser editing session.
Create keeps the new item selected. Cancel returns to the same view. Archive is reversible and the server rejects active jobs. Cancelling a job preserves cached frames; resumption is an explicit action.
No automatic recurring render jobs. Polling reads state and never submits jobs. The visible live-preview view may render transient draft images on edits and during explicitly started playback. Late project/scene/image responses must not replace a newer selection.
Loading reserves media geometry. Errors remain visible with correction/retry actions. A disconnected server preserves drafts and provides reconnect. Searches are local, clear immediately, use pagination and never submit during IME composition.
Keyboard operation uses native semantics. Dialogs trap focus natively, support Escape, and restore focus. Pixel sampling has a keyboard center-sample alternative. No drag-only functionality.
MCP tools and CLI share identical operations. Every product capability has an operation entry and generated schema. There is no permanent-delete UI or external publication in v1.

Sequence export copies all frames and the sidecar through export_artifact. The destination stays editable after validation or filesystem errors; existing data is not replaced. Individual EXR outputs and manifests are downloadable, and successful exports expose a copyable absolute path.

Each new delivery uses a parent export directory, defaulting to workspace/exports. Users select a folder in the system picker or enter any writable absolute path; no allowlist or prior startup configuration is required. choose_export_directory returns a path or cancellation, writes no grants, and does not hold the product-operation lock while waiting for the user. Cancellation and errors preserve the current destination. Folder selection blocks export submission until it finishes. The shared controls are used for native and browser deliveries and manual sequence export. Submission freezes the resolved parent with the saved scene revision; a changed destination is a different idempotent request. The worker creates one scene-name/task-ID folder after verifying every output, containing frozen sources, thumbnail, outputs and verification/manifest files. Staging happens on the destination volume; only a complete bundle is published. Existing user data is never overwritten, and symlink/path changes cannot redirect a frozen job. Retry reuses an unchanged complete bundle with the same job/snapshot identity. Export errors keep verified workspace outputs. Jobs show the path while pending and explicitly mark successful export only after publication. Completed published jobs expose the shared “打开导出文件夹” action through open_export_directory; manual sequence copies expose it after successful copying. Open errors keep a copyable path and support retry. Legacy allowed_roots remains an empty discovery field, and --export-root is accepted for script compatibility without restricting destinations.

Delivery uses directly selected container, codec, profile, depth, sampling, output color space, Gamma, alpha, range, compression and quality fields. Color space and Gamma are separate linked controls: ACES uses Linear, Rec.709 uses Gamma 2.4 or sRGB, and Rec.2020 uses PQ or HLG. A fixed transfer remains visible and disabled. The shared Python delivery capability matrix is authoritative; all transports use get_delivery_options and submit_configured_delivery. Each target is a transient draft until a job freezes its complete output description. The combined color_output alias and legacy preset APIs remain compatible with existing scripts/history; alias bookkeeping does not appear as a second color adjustment in the UI.
Linked selections prioritize the changed field, retain compatible values and announce automatic adjustments. Alpha can select a compatible 4444 profile; HDR can select a compatible depth; MXF constrains shared frame-rate choices. User-supplied invalid submission values are rejected rather than silently rewritten at submission. Stale capability responses never replace newer drafts. Pending or invalid targets block delivery, errors retain fields and offer retry, and adding/removing an output never changes other outputs. Delivery drafts are transient and intentionally stay out of URL query parameters.

The workspace opens at “选择场景”. Creating a scene selects it and opens “编辑与预览”; existing scenes have an explicit continue action. Four numbered stage buttons remain available. Stage switches preserve scene, delivery, and render-setting drafts; only project/scene replacement uses the discard guard. Stages are transient views of one in-memory editing session and intentionally do not use URL state or imply saved drafts. A step change focuses its heading. Route document titles are localized as “{stage or MCP 接口} · ChromaScript”.

Saving is explicit before stored preview jobs and delivery. Transient live preview accepts the unsaved draft without saving or creating a job. Preview actions and the editable canvas/time settings stay with the picture. The preview inspector owns preset, width, height, rational fps, total frames, final-render sampling and start timecode; changing them updates the existing shared state and live preview without stage navigation. Code editing is a native details disclosure. Delivery shows a read-only summary of those same shared settings beside linked format fields and an actual-value review, with an action returning to preview for changes. It never creates a second specification draft. Pending/invalid/duplicate delivery or unsaved scene changes explain why submission is unavailable. Only successful delivery submission goes to “任务与成果”; failure keeps the configuration. Resource estimates disappear when their input recipe changes. The queue is paginated at 8 tasks and remains active across all stages. Results belong to the selected job; another scene’s job cannot appear as the current scene’s preview. Background completion does not move keyboard focus.

Live preview opens by default, debounces draft/code/frame edits for 180 ms and waits for one in-flight request before sending the latest input. IME composition, hidden documents, other workflow stages and other viewer modes suspend work. Its raster has a maximum 480-pixel dimension and uses one sample per pixel, retaining logical scene coordinates, exact rational frame time and the same ACES sRGB view. Returned 8-bit PNGs stay in memory; no EXR, artifacts, revisions, tasks or delivery settings change. Playback is explicit, loops the selected timeline, skips display frames and waits at least 125 ms between renders. Draft changes and scene switches invalidate old replies; slow playback frames can complete for the unchanged draft. Failures pause playback, preserve the draft and the last valid image with explicit stale/error feedback and retry. Original pixel inspection belongs only to stored keyframes. Manual render actions open that stored-frame view.

Output color standardization requires separate gamut and transfer controls plus server-described fixed target display luminance. The combined color_output remains an API compatibility alias only. A legacy daemon must produce an actionable update/retry message and block delivery instead of restoring the mixed dropdown. Service updates preserve projects, revisions, jobs and artifacts; an idle local daemon can be restarted to apply the schema.

Original float-frame inspection is requested only in the visible preview step. Historical missing caches cannot interrupt scene selection or delivery setup; inspection errors remain explicit when the user opens preview.

Scene color selection uses display-referred OKLCH (D65) for the sRGB SDR preview. It is a perceptual selection space, not an HDR appearance simulation. `resolve_color` inspects RGB without changing it, or reduces requested chroma at fixed lightness/hue to fit sRGB, inverts the exact ACES preview view, and returns RGB in the parameter's declared space. The selected color is forward-rendered for verification; sRGB-declared parameters use the inverse utility input encoding. Alpha is outside this RGB-only operation. Negative and >1 original values are never clamped in storage. Opening/cancelling/Escape preserves original values exactly; Apply updates only the local scene draft, and saving remains explicit with revision checks. Delayed/failed conversions cannot enable Apply or replace newer choices; retries preserve the candidate. Sliders and plane arrow keys provide alternatives to dragging. Errors retain advanced RGB access and offer retry; viewing limits and gamut adjustments are shown in text.

Gamut choices include P3-D65, Rec.709, BT.2020/Rec.2020, ACEScct, ACEScg and retained ACES2065-1. All remain discoverable with unavailable options disabled and explained. ACEScct selects its AP1 log curve, promotes integer precision to at least 10-bit, and exposes no display luminance. ACEScg requires float EXR; log EXR preserves unbounded values. Video log values outside integer storage must fail, never silently clip. Native AP1/ACEScct tags are unspecified plus an explicit declaration and manual import guidance.

Delivery follows the installed Resolve 21 manual's separation of output processing, file color/gamma tags and data levels, within actual local encoding support. P3-D65 accepts Gamma 2.2, Gamma 2.4, Gamma 2.6, sRGB and PQ where the container can represent them. Rec.709 also offers Gamma 2.2 and Gamma 2.6. A gamut change retains a compatible gamma; ProRes does not imply sRGB, and P3-D65/sRGB remains the valid Display P3 encoding. MOV Gamma 2.4/2.6 retains unspecified TRC with a native comment declaration and requires manual input interpretation; colr is never supplemented by gama. P3 Gamma 2.4/2.6 and Rec.709 Gamma 2.6 remain limited to this implemented MOV declaration workflow. Read-only Gamma Tag and import notes must distinguish that declaration from automatic color recognition, including the Rec.709 Gamma 2.4 default. File tag fields are read-only and derived from the output. Gamma 2.6 does not change the fixed ACES view, white point or peak luminance. Auto is the default data-level draft choice, with explicit Video/Limited and Full options; unsupported overrides stay disabled with reasons. Auto resolves to a concrete range in the immutable DeliveryPreset before queueing. Existing full/limited API values and the limit alias remain compatible; video and Auto aliases share the same strict models. The web client requires resolve-21-delivery-v1 capability responses; older daemons preserve drafts and require update/retry. Source versions, the implemented subset and import limits are recorded in docs/RESOLVE_IMPORT.md.

Code generation and internal processing are fixed float32 linear ACEScg (AP1). SceneSpec.code always returns straight-alpha ACEScg; literal RGB follows the same contract. Parameter.color_space describes only stored parameter RGB; the renderer converts it to ACEScg before shader execution. There is no selectable scene input or working space. ColorWorkflow shows this invariant in preview and delivery; the code editor and ColorField explain it in context. The sRGB browser preview is independent of user-selected delivery gamut/gamma. Display delivery applies one ACES output transform, while ACES scene encodings bypass display rendering. Alpha bypasses color processing and original extended RGB is preserved. Existing shared discovery and documentation operations expose this contract equally to HTTP, MCP and CLI.

Motion preview uses the dedicated h264-srgb-preview built-in through render_preview on every transport; h264-review remains a Rec.709 delivery preset. The browser accepts motion artifacts only after successful verification of H.264/yuv420p, Rec.709 primaries and matrix, IEC 61966-2-1 transfer, and the sRGB ACES output recipe. Filename aliases never bypass these checks. Legacy Gamma 2.4 previews and non-sRGB deliveries require a new explicit motion preview; existing artifacts remain downloadable. Preview jobs never inherit project/delivery output settings.
