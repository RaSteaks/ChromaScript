# ChromaScript interaction contract

New animation jobs freeze destination-v1 storage: float EXR or SDR screenshot intermediates and selected video render in a task-owned staging directory on the export volume, then publish by rename. In master mode cancellation/interruption retains verified frames; resume checks frozen source/runtime/OCIO/GPU and per-frame hashes. Workspace contains job metadata/logs only. Artifact IDs use bundle-relative paths and resolve both staging and published locations from the frozen snapshot. master-archive is a virtual ZIP64 native download with no server-side ZIP or stored byte size; export_artifact exposes the same capability on CLI/MCP. ZIP downloads restart after interruption and close their generator on disconnect. Historic artifacts keep workspace defaults; no existing task files or snapshots are migrated. Result copy explains the on-demand download without changing draft, focus, preview or output precision behavior.
Product evidence: the accepted ChromaScript plan, shared Python models, and the operation registry.
Locale: zh-CN. Dates use Asia/Taipei; units and code identifiers remain explicit.

Master-first animation delivery: new blank animations use the float engine; SDR remains explicitly selectable. Final output defaults to ACEScg Float32 ZIP masters only and 2×2 spatial supersampling, with 1×1 and 4×4 alternatives; the low-resolution preview stays single-sampled. MotionWorkbench owns editable positive-integer custom dimensions/frame count and a rational numerator/denominator text field alongside rate presets. GPU, memory and codec limitations fail explicitly. Use existing Field, Button, Modal and Notice tokens; no new visual tokens. Regenerate/check tokens.css from the unchanged frontmatter.

MotionWorkbench distinguishes measured float-pipeline verification from revision-bound source-color review. An optional shared Modal records reviewer and evidence against the revision captured when opened; conflicts retain form text, and cancellation changes no review. A saved review is an explicit attestation, not automatic shader certification. Unreviewed shaders remain usable. Dirty/new revisions show unreviewed; job results show the frozen review and independent native video tag verification.

Both animation engines stage intermediate frames, bundler outputs, encoder files and final output on the selected export volume. Workspace keeps task metadata/logs; system browser temporary profiles may remain local. Missing/replaced volume fails rather than falling back locally. DeliveryDestination explains direct external-disk writing. Master-mode float recovery retains verified EXRs; video-only and SDR rerender on retry.

Mandatory exact video-tag policy supersedes the earlier MOV declaration-only workflow described in historical sections: all new video output must have native gamut and transfer tags matching actual pixel encoding. Default SDR is Rec.709/sRGB. Pure Gamma 2.4/2.6 and AP1/ACEScct video remain visible but disabled with a reason, across all containers, CLI/MCP and legacy presets. Comments and unspecified tags cannot satisfy the requirement. EXR scene encodings and DPX numeric Gamma remain available. Missing/mismatched actual codec tags or MOV/MP4 colr prevents publication.

Mutations are pessimistic; keep values until confirmed and disable duplicate submits. Saving code sends expected_revision_id. Conflicts preserve the local draft and offer reload/copy. Scene/project changes guard unsaved drafts; browser beforeunload is used only when dirty.

MotionWorkbench and CodeEditor own the independent “动画代码” session, with MotionSpec and motion_scene/motion_revision as its source of truth. The existing SceneSpec/ACEScg contract below applies to WGSL. TypeScript code and canvas/time drafts survive navigation. Explicit saves detect revision conflicts and never replace newer edits with a late acknowledgement. Animation/project replacement guards unsaved drafts through Modal; creation selects the new animation. With a project loaded and no animation open, guidance points to the picker and template actions without adding duplicate controls. Saved animation and job lists have bounded pagination. MotionPreview debounces unsaved drafts outside IME composition and never saves/submits a job. Obsolete replies are discarded; candidates mount before replacing the last working picture. Errors retain drafts and the last picture with explicit stale/error status and a retry action. Playback begins only on Play, pauses when hidden, and supports keyboard seeking.

The visible animation editor reads the currently open animation through get_motion_scene once per second after each completed read. HTTP/MCP/CLI saves share this revision source. A changed revision replaces a clean draft's complete code/name/canvas/time specification and selected library metadata without remounting the editor or moving focus; MotionPreview independently compiles the accepted source and never starts playback or a render job. Dirty drafts retain their original expected_revision_id and all fields, with persistent external-update feedback and the existing copy/reload/discard controls. New animations never replace the current selection automatically. Reads are serial and time out after 10 seconds; explicit operations, IME composition in code or metadata, inactive views and hidden documents suspend/cancel them. Return to a visible editor triggers an immediate check. Late responses must recheck project, animation, saved revision and current draft before application. Failed reads retry after 2 and 4 seconds, then pause after the third consecutive failure; the existing connection control resumes synchronization. Sync feedback owns its errors and cannot clear explicit save/conflict feedback. Polling writes no revisions, artifacts or jobs.

The three-float-v1 engine uses only local Three.js imports in an opaque-origin allow-scripts iframe without editor tokens/same-origin access. Source returns scene/camera/update from a factory; SDR remotion-sdr-v1 compositions independently support React DOM/SVG/ThreeCanvas; historical records without an engine normalize to SDR on read, never by rewriting stored data. GPU RGBA32F render/readback is verified using negative, >1 and non-half-representable values. Numeric source RGB is linear Rec.709; the host unassociates linear alpha and converts through pinned OCIO to ACEScg/AP1. Alpha never enters OCIO. Float EXR preserves original RGB without display rendering; preview uses the generated OCIO ACES 2.0 SDR sRGB shader. Float export offers EXR Half/Float with optional video, or video-only SDR H.264 / HEVC Main10 PQ/HLG / Apple ProRes 422 HQ MOV (sRGB, PQ, HLG). Float video uses one ACES output transform; PQ/HLG target 1000 nits. ProRes is opaque 10-bit 4:2:2, budgets compressed HQ macroblocks with 20% margin and mux overhead, and publishes with video/quicktime MIME. HDR is never shown as an ordinary in-page video; results use an sRGB thumbnail. Native fields from get_motion_delivery_options control output choices and explain missing encoders. Video requires even dimensions, EXR allows odd dimensions. Submission freezes output, source, revision, rational rate, runtime, OCIO and destination. SDR sources offer sRGB H.264 or ProRes 422 HQ with no ACES view and no float/HDR precision claim. Source-specific output discovery is stale-safe; switching source cannot submit incompatible previous options. Every EXR is read back and verified; actual video decoding verifies codec/depth/rate/color tags. No invented HDR mastering metadata. Failures retain drafts; master-mode retry reuses verified EXRs, video-only retries restart from zero. Both refuse source/runtime/OCIO drift. Publication is atomic at the frozen destination. All discovery, compilation, transient frame preview, export and original-pixel inspection are exposed through the shared HTTP/CLI/MCP registry. render_motion_frame returns native PNG content plus original ACEScg statistics without storing a job or revision.

Animation discovery loads projects, templates, capabilities and export options independently. Successful project reads remain usable when another discovery call fails. Loading and failed project reads never imply an empty workspace or invite creation of replacement projects. Missing-operation HTTP 404/405 responses explain that the local service must be restarted, with explicit reconnect/retry; mutations are not replayed. A successful discovery retry clears its own errors without discarding drafts or save/conflict feedback. An idle local service upgrade preserves all stored records and the current browser editing session.
Create keeps the new item selected. Cancel returns to the same view. Archive is reversible and the server rejects active jobs. Cancelling a job preserves cached frames; resumption is an explicit action.
No automatic recurring render jobs. Polling reads state and never submits jobs. The visible live-preview view may render transient draft images on edits and during explicitly started playback. Late project/scene/image responses must not replace a newer selection.
Loading reserves media geometry. Errors remain visible with correction/retry actions. A disconnected server preserves drafts and provides reconnect. Searches are local, clear immediately, use pagination and never submit during IME composition.
Keyboard operation uses native semantics. Dialogs trap focus natively, support Escape, and restore focus. Pixel sampling has a keyboard center-sample alternative. No drag-only functionality.
MCP tools and CLI share identical operations. Every product capability has an operation entry and generated schema. There is no permanent-delete UI or external publication in v1.

Sequence export copies all frames and the sidecar through export_artifact. The destination stays editable after validation or filesystem errors; existing data is not replaced. Individual EXR outputs and manifests are downloadable, and successful exports expose a copyable absolute path.

Each new delivery uses a parent export directory, defaulting to workspace/exports. Users select a folder in the system picker or enter any writable absolute path; no allowlist or prior startup configuration is required. choose_export_directory returns a path or cancellation, writes no grants, and does not hold the product-operation lock while waiting for the user. Cancellation and errors preserve the current destination. Folder selection blocks export submission until it finishes. The shared controls are used for native and browser deliveries and manual sequence export. Submission freezes the resolved parent with the saved scene revision; a changed destination is a different idempotent request. The worker creates one scene-name/task-ID folder after verifying every output, containing frozen sources, thumbnail, outputs and verification/manifest files. Staging happens on the destination volume; only a complete bundle is published. Existing user data is never overwritten, and symlink/path changes cannot redirect a frozen job. Retry reuses an unchanged complete bundle with the same job/snapshot identity. Export errors keep verified workspace outputs. Jobs show the path while pending and explicitly mark successful export only after publication. Completed published jobs expose the shared “打开导出文件夹” action through open_export_directory; manual sequence copies expose it after successful copying. Open errors keep a copyable path and support retry. Legacy allowed_roots remains an empty discovery field, and --export-root is accepted for script compatibility without restricting destinations.

Delivery uses directly selected container, codec, profile, depth, sampling, output color space, Gamma, alpha, range, compression and quality fields. Color space and Gamma are separate linked controls: ACES uses Linear, Rec.709 video uses exactly tagged sRGB or Gamma 2.2, and Rec.2020 uses PQ or HLG. A fixed transfer remains visible and disabled. The shared Python delivery capability matrix is authoritative; all transports use get_delivery_options and submit_configured_delivery. Each target is a transient draft until a job freezes its complete output description. The combined color_output alias and legacy preset APIs remain compatible with existing scripts/history; alias bookkeeping does not appear as a second color adjustment in the UI.
Linked selections prioritize the changed field, retain compatible values and announce automatic adjustments. Alpha can select a compatible 4444 profile; HDR can select a compatible depth; MXF constrains shared frame-rate choices. User-supplied invalid submission values are rejected rather than silently rewritten at submission. Stale capability responses never replace newer drafts. Pending or invalid targets block delivery, errors retain fields and offer retry, and adding/removing an output never changes other outputs. Delivery drafts are transient and intentionally stay out of URL query parameters.

The workspace opens at “选择场景”. Creating a scene selects it and opens “编辑与预览”; existing scenes have an explicit continue action, and each scene row shows its last-saved time while its accessible name stays the scene name. Four numbered stage buttons remain available. Stage switches preserve scene, delivery, and render-setting drafts; only project/scene replacement uses the discard guard. Stages are transient views of one in-memory editing session and intentionally do not use URL state or imply saved drafts. A step change focuses its heading. Route document titles are localized as “{stage or MCP 接口} · ChromaScript”.

Saving is explicit before stored preview jobs and delivery. Transient live preview accepts the unsaved draft without saving or creating a job. Preview actions and the editable canvas/time settings stay with the picture. The view switch precedes the stored-render actions, which are grouped and named as renders of the saved revision. Scene parameters lead the inspector so they are adjusted beside the picture; canvas/time settings follow in the same inspector. The preview inspector owns preset, width, height, rational fps, total frames, final-render sampling and start timecode; changing them updates the existing shared state and live preview without stage navigation. Code editing is a native details disclosure. Delivery shows a read-only summary of those same shared settings beside linked format fields and an actual-value review, with an action returning to preview for changes. It never creates a second specification draft. Pending/invalid/duplicate delivery or unsaved scene changes explain why submission is unavailable. Only successful delivery submission goes to “任务与成果”; failure keeps the configuration. Resource estimates disappear when their input recipe changes. The queue is paginated at 8 tasks and remains active across all stages. A task row shows its stage only while queued or running; finished states show the localized outcome alone. Results belong to the selected job; another scene’s job cannot appear as the current scene’s preview. Background completion does not move keyboard focus.

Live preview opens by default, debounces draft/code/frame edits for 180 ms and waits for one in-flight request before sending the latest input. IME composition, hidden documents, other workflow stages and other viewer modes suspend work. Its raster has a maximum 480-pixel dimension and uses one sample per pixel, retaining logical scene coordinates, exact rational frame time and the same ACES sRGB view. Returned 8-bit PNGs stay in memory; no EXR, artifacts, revisions, tasks or delivery settings change. Playback is explicit, loops the selected timeline, skips display frames and waits at least 125 ms between renders. Draft changes and scene switches invalidate old replies; slow playback frames can complete for the unchanged draft. Failures pause playback, preserve the draft and the last valid image with explicit stale/error feedback and retry. Original pixel inspection belongs only to stored keyframes. Manual render actions open that stored-frame view.

Output color standardization requires separate gamut and transfer controls plus server-described fixed target display luminance. The combined color_output remains an API compatibility alias only. A legacy daemon must produce an actionable update/retry message and block delivery instead of restoring the mixed dropdown. Service updates preserve projects, revisions, jobs and artifacts; an idle local daemon can be restarted to apply the schema.

Original float-frame inspection is requested only in the visible preview step. Historical missing caches cannot interrupt scene selection or delivery setup; inspection errors remain explicit when the user opens preview.

Scene color selection uses display-referred OKLCH (D65) for the sRGB SDR preview. It is a perceptual selection space, not an HDR appearance simulation. `resolve_color` inspects RGB without changing it, or reduces requested chroma at fixed lightness/hue to fit sRGB, inverts the exact ACES preview view, and returns RGB in the parameter's declared space. The selected color is forward-rendered for verification; sRGB-declared parameters use the inverse utility input encoding. Alpha is outside this RGB-only operation. Negative and >1 original values are never clamped in storage. Opening/cancelling/Escape preserves original values exactly; Apply updates only the local scene draft, and saving remains explicit with revision checks. Delayed/failed conversions cannot enable Apply or replace newer choices; retries preserve the candidate. Sliders and plane arrow keys provide alternatives to dragging. Errors retain advanced RGB access and offer retry; viewing limits and gamut adjustments are shown in text.

Gamut choices include P3-D65, Rec.709, BT.2020/Rec.2020, ACEScct, ACEScg and ACES2065-1. All remain discoverable, with unsupported choices disabled and explained. Scene-linear and scene-log ACES outputs are EXR workflows; ACEScct uses AP1 log and preserves unbounded float values. Native video tags cannot describe AP1/ACEScct exactly, so new log video is unavailable. Scene encodings have no target display peak luminance.

Delivery follows the installed Resolve 21 separation of actual processing, file color/gamma tags and data levels. Native video gamut and transfer identifiers are mandatory, checked against actual pixels/recipe and native file headers; comments cannot replace missing tags. P3-D65 supports Gamma 2.2, sRGB and PQ in verified containers; Rec.709 video supports sRGB and Gamma 2.2. Pure Gamma 2.4/2.6 and AP1/ACEScct video are disabled across containers. Current MXF writing does not preserve sRGB transfer, so that combination is disabled too. Existing aliases/presets retain historical definitions but cannot bypass submission/encoding/verification policy. Default video uses Rec.709/sRGB; raw EXR remains the master. Auto is the default data-level draft and freezes to the actual codec range. Full/Video overrides remain restricted by actual native support. Field tags are read-only and derived from output. The UI retains the resolve-21-delivery-v1 capability shape and source revisions; docs/RESOLVE_IMPORT.md explains historical files separately from current delivery policy.

Code generation and internal processing are fixed float32 linear ACEScg (AP1). SceneSpec.code always returns straight-alpha ACEScg; literal RGB follows the same contract. Parameter.color_space describes only stored parameter RGB; the renderer converts it to ACEScg before shader execution. There is no selectable scene input or working space. ColorWorkflow shows this invariant in preview and delivery; the code editor and ColorField explain it in context. The sRGB browser preview is independent of user-selected delivery gamut/gamma. Display delivery applies one ACES output transform, while ACES scene encodings bypass display rendering. Alpha bypasses color processing and original extended RGB is preserved. Existing shared discovery and documentation operations expose this contract equally to HTTP, MCP and CLI.

Motion preview uses the dedicated h264-srgb-preview built-in through render_preview on every transport; h264-review remains a Rec.709 delivery preset. The browser accepts motion artifacts only after successful verification of H.264/yuv420p, Rec.709 primaries and matrix, IEC 61966-2-1 transfer, and the sRGB ACES output recipe. Filename aliases never bypass these checks. Legacy Gamma 2.4 previews and non-sRGB deliveries require a new explicit motion preview; existing artifacts remain downloadable. Preview jobs never inherit project/delivery output settings.

Blank creation is independent of the example catalogue: create_scene(project_id) defaults to a minimal transparent WGSL shader with no parameters; create_motion_scene(project_id, engine?) defaults to an empty float scene for three-float-v1, or a minimal transparent SDR component when remotion-sdr-v1 is explicitly selected. Explicit spec bypasses templates; explicit mismatched animation engine/template/spec is rejected. Empty source text is not required: blank scaffolds remain runnable and strictly validated. The browser exposes primary blank creation in both workspaces, with optional examples; animation examples are collapsed by default. Blank creation uses the same revision, project membership, draft guard and selection/focus flow as example creation. Every entry point is identical on HTTP/MCP/CLI; no example selection is a prerequisite.


ProjectAudio is the canonical shared project-soundtrack editor (source: audio.py operation models and frozen delivery snapshots). Its app-owned Modal blocks project switching while open; unsaved timeline closure requires the shared discard dialog. Save/retry errors retain fields, and revision conflicts never overwrite remote changes. Copy draft and explicit discard/reload are available. Uploaded/generated assets persist separately; adding/removing a clip only edits the draft until Save. Existing assets are immutable and source audition never autoplays. Asset lists have five-item pagination. Native select/file/audio controls retain platform interaction; numeric drafts permit intermediate empty values and validate on save. Import and synthesis show honest indeterminate status, block duplicate actions, and do not automatically retry uncertain writes. Closing during a write is blocked. Long dialog bodies scroll within the existing modal; narrow timing forms stack. Project audio applies to all scenes' new deliveries, freezes with jobs and is explicitly described as unavailable in editing previews. UI, MCP and CLI share the same operation registry.


Animation storage estimates are owned by MotionStorageEstimate and estimate_motion_render (motion.py). Debounce valid numeric/output/destination drafts for 300 ms, suspend requests during IME/folder selection/inactive views, and ignore aborted or superseded responses. Any recipe edit immediately hides the obsolete estimate; name/code-only changes do not request storage again. A visible refresh action rechecks disk and project audio. Failures preserve all authoring/delivery drafts and offer retry without blocking the authoritative submit-time check. Label uncompressed masters, storage budgets and actual free space separately; unknown ZIP/video compression is not a guarantee. The estimator creates no directories, revisions or jobs. Submit uses the same budget, including audio and distinct workspace/export volumes, and rechecks current availability. Dynamic free space never changes the frozen job identity.

Animation multi-file editing: MotionSpec.code remains the fixed entry; files maps relative module paths to source. MotionSourceEditor owns file selection, add-path validation and draft deletion through the shared Modal. Every shared directory prefix must use identical casing in the editor, compiler and backend so case-insensitive export volumes preserve the manifest. Adding does not auto-import or schedule a chapter: the entry explicitly controls timing. File changes join the same dirty guard, late-save protection, revision conflict, IME suspension and preview candidate flow as entry edits. Copy all sources includes every file; deletion requires confirmation and leaves historical revisions intact. HTTP/MCP/CLI use the same create/update/compile/render operations and freeze the full graph. Exports carry a sources/ tree for multi-file animations; single-file exports keep their original paths.

Successful animation submission ends its request identity; a subsequent explicit export creates a new key and freezes the current project soundtrack. Uncertain network outcomes retain the original key for deliberate retries. New projects persist sRGB output explicitly, and submit_default_delivery uses Rec.709/sRGB ProRes HQ through the shared configured-delivery path. Legacy implicit pipelines, explicit presets and cloned project color settings retain their original interpretation and remain subject to exact video-tag validation.


MotionWorkbench adds an explicit “导出模式” native select: “保留 EXR 母版” (unchanged default) or “仅视频”. Video-only hides EXR precision, keeps a compatible selected video or selects an available video, and excludes the master-only video choice. Toggling back restores the last chosen EXR depth. Preview, source drafts and saved revisions are unaffected. Discovery advertises video_only; older services cannot offer the mode. MotionStorageEstimate and DeliveryDestination describe the selected outputs accurately: video-only writes no EXR, retains one transient float transport on the destination, encodes each frame once, and uses a content-dependent compressed video budget rather than a full raw sequence. Interruptions require an explicit restart from frame zero; already-published bundles recover without rendering.
